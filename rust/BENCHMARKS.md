Notes on the C++ baseline:
- `save` (70 s) is more than twice `load` (34 s) — the writer re-encodes every field, no fast path.
- `find_ci` (138 s) case-folds every row per cell; `find_cs` (10.4 s) does not.
- `sort num` (241 s) parses `std::stod` per comparison and case-folds nothing; string sorts are 6–8× faster.
- Peak RSS for `big.csv` is 3.1 GB for a 1.97 GB file (≈1.1 GB of row-string overhead on 16 M rows).

## Parity

Oracles generated by the C++ harness in `testdata/out/cpp/` (`*.saved.csv` for every §7.2 file, `big-sort-id.sorted.csv` for the `--sort-col 0` run). Byte-for-byte comparison against `tc-bench` happens in phase 1.

Oracle observations (input → C++ output):
- `utf8bom.csv` 1259638 → 1259635 B: the 3-byte BOM is dropped on save (parity rule).
- `utf16le.csv` 55048282 → 53048282 B: CRLF terminators become LF (C++ always writes `\n`), exactly 2 bytes × 1 M rows.
- `ragged.csv` 3598587 → 4150900 B: short rows are padded to `n_cols`.
- `nul_bytes.csv` 13 → 11 B: NUL bytes are dropped.
- `backslash.csv` 26797 → 27965 B: `\"`/`\,` escapes are re-quoted RFC style.
- `edge/unterminated_quote.csv` → 0 B: the C++ record loss that divergence D1 fixes.
- `edge/latin1_c1.csv` 15 → 12 B: C++ drops Latin-1 bytes 0x80–0x9F (D5).
- `edge/single_cell.csv` 1 → 2 B: the missing line terminator is added on save.
